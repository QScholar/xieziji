## 行为

预览栏新增“放大预览”按钮，纸张本身也可点击。放大视图把当前页已渲染的 SVG 复制到 `<dialog>` 中，只是屏幕上的缩放，不重新请求 `/api/preview`，因此不会产生新任务、新随机种子或新 G-code；下载与写字仍使用同一份缓存路径。

| 操作 | 结果 |
| --- | --- |
| 点击纸张 / “放大预览” | 打开当前页的放大视图，初始为整页适配，缩放 100% |
| 滚轮 / 触控板 | 以光标位置为中心缩放，范围 25%–1600% |
| 拖动（鼠标 / 单指） | 平移；触控屏双指为捏合缩放 |
| 双击 | 放大到 2.4 倍；已放大时回到整页 |
| `+` / `-` / `0` | 以视图中心放大、缩小、整页显示 |
| 方向键 / Shift + 方向键 | 平移 40 / 120 px |
| 缩放后点“整页显示” | 回到适配；100% 时按钮禁用 |
| 关闭按钮 / Esc | 关闭；焦点回到“放大预览” |

## 与预览数据的同步

`displayPaper` 写入新 SVG 时，如果放大视图已打开，会把同一份 SVG 重新挂载并保持缩放与可见区域（窗口尺寸变化同样按可视中心补偿）。所以在放大视图里切换输出页、改边距或坐标后，看到的是更新后的路径，而不是旧帧。

放大画布的基准尺寸按 SVG 自身的 `viewBox` 纵横比计算（不是固定 A4 竖版），因此横向 297 × 210、表格模式与其他自定义范围都按实际纸张比例铺满可用区域。

## 兼容性

- 不新增接口、不修改请求体；`/api/preview`、`/api/coordinate-preview`、`/api/line-pitch` 行为不变。
- 未生成预览时按钮保持禁用，纸张点击无动作。
- 依据已部署文件校验：`deploy/verify_line_pitch.py` 的 gcode 断言不受影响，本次未改后端。

## 验证

浏览器（本地 8086 端口副本，真实字体 `blood8-2_kvenjoy_blood8`，模拟控制端）：

- 生成 1 页预览后打开放大：画布 515 × 679 px，读取到 158 条 `polyline`，与主预览一致；缩放标签 100%。
- 滚轮上滚 600：205%，变换为 `translate(59.61, -327.78) scale(2.054)`；中心不动。
- 拖动 (120, 60)：平移量精确等于拖动距离，`is-dragging` 在松开后清除。
- 双击：在 135% 与整页之间切换；`+`/`-` 步进 1.35 倍；`0` 复位；方向键单次 40 px。
- Esc 关闭后焦点回到 `zoomPreview`；点击纸张可重新打开且仍为 100%。
- 横向 297 × 210：画布 894.6 × 679，比例 1.318，与 `viewBox` 361 × 274 一致。
- 双指捏合（合成 PointerEvent）：100% → 200%，中心按两指中点保持。
- 打开状态下改上边距 30 → 45：放大视图的 `#writable-area y` 同步为 45，缩放与位置保持。
- 打开状态下切到第 2 页：`#writing-paths` 由 158 条变为 33 条，仍保持打开。
- 视口 420 × 820：工具栏换行后不溢出（352 px 宽，内边距内），舞台 380 × 616，画布居中。

## 部署

```powershell
.\deploy\deploy_preview_zoom.ps1
```

脚本校验在线文件哈希、打包哈希、源码树干净，解包后 `compileall`，重启 `Xieziji-Web`，断言线上 HTML 含对话框与提示、`app.js` 含缩放/平移/捏合/复位实现且未新增预览请求、两份样式表都已包含放大规则、固定种子的 `/api/preview` 仍返回路径；控制器 PID、任务号与确认数不变。失败由 `git checkout HEAD` 回滚并重启。

脚本需保存为 UTF-8 with BOM：Windows PowerShell 5.1 无 BOM 时按 ANSI 读取，中文字面量会损坏。

实际执行记录：`Result=UPDATED`，控制器 PID 10168 未变，任务号 `fb5c24e70e7941009eafcf5dbe3a1e3f` 与确认数 10180 未变，COM5 仍连接、Idle、抬笔；固定种子预览返回 14203 字节 SVG / 476 点。线上 8080 浏览器实测：生成 1 页预览后打开放大，读取 158 条路径，滚轮 187%，日志中 `/api/` 请求数不变。
