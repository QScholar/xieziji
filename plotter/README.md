# 纸间 · 本地写字台

浏览器负责编辑与预览，连接写字机的电脑运行 Python 后端。直接读取现有 `.gfont` 文件，不需要启动奎享主程序。

当前功能：305 个现有字体的选择与搜索、中文/英文排版（中文与英文可分别设置字高与字体）、自动换行、A4 横竖方向、字距/行距/边距调整、SVG 笔画预览、G-code 下载、串口连接、写入进度、暂停与继续、任务日志。没有图片转路径、文档导入或多页连续送纸。

## Windows 启动

需要 Python 3.10 或更新版本。打开 PowerShell，进入项目根目录：

```powershell
cd 'C:\写字机\奎享雕刻'
.\plotter\start.ps1
```

脚本在 `plotter/.venv` 创建独立环境；优先使用项目已有的离线 pyserial 3.5 安装包。浏览器打开 `http://127.0.0.1:8080`。如果系统的 PowerShell 策略不允许运行脚本，可直接运行以下命令：

```powershell
py -3 -m venv plotter\.venv
.\plotter\.venv\Scripts\python.exe -m pip install -r plotter\requirements.txt
.\plotter\.venv\Scripts\python.exe -m plotter.server
```

只验证网页流程、不连接真实设备：

```powershell
.\plotter\start.ps1 -Simulate
```

使用已有 Python 环境也可以直接执行 `python -m plotter.server`，并通过 `--font-dir` 指定字体目录、`--jobs-dir` 指定任务目录、`--port` 更改端口。前端静态资源随后端一起提供，无需 Node、构建工具或外部 CDN。

## 写字机电脑 / 202.206.255.200

后端应在实际插着 USB 串口的电脑上运行。打包部署需要 `plotter/` 源码和 `analysis/gfont.py`；原字体可继续使用机器上已有的目录。不要复制本机的 `.venv` 到另一台电脑。

该服务器已有 Python 3.10 和 pyserial 3.5，可在部署根目录直接启动：

```powershell
py -3.10 -m plotter.server --font-dir 'C:\tools\奎享雕刻\奎享雕刻\gcodeFonts'
```

服务器浏览器访问 `http://127.0.0.1:8080`。另一台电脑可使用 SSH 转发，无需开放服务器防火墙：

```powershell
ssh -N -L 18081:127.0.0.1:8080 202.206.255.200
```

保持 SSH 窗口运行，在客户端浏览器打开 `http://127.0.0.1:18081`。本地服务会将转发端口视为不同 Host；应在服务器启动时使用 `--allow-origin-port` 参数允许该端口：

```powershell
py -3.10 -m plotter.server --font-dir 'C:\tools\奎享雕刻\奎享雕刻\gcodeFonts' --allow-origin-port 18081
```

若希望局域网直接访问，可设置访问令牌并显式允许服务器地址：

```powershell
$env:PLOTTER_TOKEN = 'replace-with-your-own-long-random-token'
py -3.10 -m plotter.server --host 0.0.0.0 --allow-host 192.168.1.100
```

替换为机器真实的局域网地址，在网页“服务访问令牌”处输入相同令牌。默认仅监听本机；示例不自动改防火墙。公网访问应通过 SSH 隧道或有 HTTPS 的受控代理。

## 使用流程

1. 选择字体、输入文字，点击“生成路径预览”。缺字或文字超出纸张边距时会明确报错。
2. 关闭原上位机对串口的连接，刷新串口列表，选择 COM5 并连接。
   可以先点击“检查原点与配置（只读）”，验证控制器状态；该操作不移动机器。
3. 放好纸张，将笔定位到纸张左上角，并在设备端确认机器坐标为 `(0,0,0)`。X+ 向右，Y+ 向下。网页不提供自动回零或任意指令输入。
4. 勾选纸张/原点确认，点击“开始写字”。后端复查机器状态与配置后才开始发送。
5. “暂停”发送 GRBL feed hold；可能需要短暂减速，笔不会自动抬起。“继续”恢复当前任务。
6. 全部指令确认后，后端继续等待实际 Idle，并核对最终零坐标，才显示完成。任务结束抬笔并返回纸张左上角。

实时状态使用 `?`，暂停/继续使用 `!`/`~`；对应含义见 [GRBL 官方命令文档](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Commands)。进度显示控制器已确认的指令数，未必等于即时纸面绘制比例。

## 当前机器配置与限制

- 真实模式限定已实测的 `1.3a.20221114` 固件，115200 baud，Z0 抬笔 / Z10 落笔，默认绘制 1800 mm/min，空移 3000 mm/min。
- 执行前检查 Idle、机器零坐标、G54/G92/刀具偏移为零、方向参数 `$3=7`、步数 `$100=80/$101=80/$102=100`、行程/速度范围、空启动块及原有的限位/回零配置。
- 控制器错误、串口中断或确认超时后，停止发新指令并尽力发送 feed hold，任务进入失败状态。此时可能保留已排队的动作；应先在设备端处理、重新定位并重启服务，不会自动清空队列或解锁。
- 服务启动不会自动连接机器或落笔。退出服务前先完成任务；不要在任务中关闭后端、拔线或刷新操作替代物理停机。
- 字形路径已恢复；原软件的字距、基线、随机变化规则未全部恢复，当前采用自建排版。
- 程序不依赖 Windows 专用 API，Python 后端和网页可迁移到 Linux/macOS；尚未在这些系统和设备上做实机验证。

任务保存到 `plotter/jobs/<任务编号>/`，包含预览、G-code、元数据、执行前查询、串口日志与状态。内存保留最近 8 个预览用于启动/下载，旧文件仍在磁盘；重启后需重新生成预览。单份内容最多 3000 字、200000 路径点，只允许同时执行一个任务。每次开始都会新建执行目录，同一预览可在确认新原点后再次写入。
