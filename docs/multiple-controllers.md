# 多台写字机与启动校准

业务后端使用 `--controllers-file /private/controllers.json`，或环境变量 `PLOTTER_CONTROLLERS_FILE` 指定私有注册表。内容为数组，每项包含 `id`、`name`、`url`、`token`，树莓派项另设 `contact_startup: true`。编号为小写字母开头、至多 40 位的小写字母／数字／连字符。地址和令牌仅由后端持有，不返回浏览器。文件属于部署数据，不提交版本库。

第一项沿用原任务目录和设备档案。后续项使用 `jobs/controllers/<id>/`，隔离设备档案、共享编辑内容、预览、执行记录和 ETA。每台控制器独立持有串口及任务线程。第一项继续使用原 Windows 设备故障看护；树莓派使用本机 systemd，不由 Windows 看护进程重启。

前端从 `GET /api/controllers` 获得名称与编号。所有设备请求附带 `X-Plotter-Controller`；多设备模式下，缺少编号的 POST 或未知编号均被拒绝，不回退到默认机器。切换前保存旧设备界面，清除原点确认和旧状态，载入目标设备的配置及预览；丢弃旧设备的迟到响应。切换不发送断开、暂停、终止或运动命令，另一台任务继续执行。

## 树莓派每次使用前的流程

树莓派控制服务设置 `PLOTTER_CONTACT_STARTUP=1`。该设备采用通用 GRBL，顶部逻辑 Z0、纸面逻辑 Z13.5，校准上移速度固定为 100 mm/min。

1. 无论上次以什么状态结束，使用前先切断写字机电源，再换笔或放笔，让笔尖接触纸面，笔架位于最低位。
2. 不要随意调整弹簧控制。重新通电后人工确认笔尖仍接触纸面、笔架仍在最低位，再连接设备。
   如果固件仍处于已停稳的 `Door:0` 或 `Hold:0`，树莓派模式会先软复位放弃旧队列，等待启动确认、核对机器坐标未变并确认 Idle 后连接；不会发送恢复旧任务的 `~`。门未闭合或仍在运动的状态不会被放行，原 Windows 设备保持严格 Idle 检查。
3. 前端勾选断电换笔及最低位确认后，主动点击“上移 13.5 mm 并置零”。控制端要求 `power_cycled`、`pen_on_paper`、`bottom_confirmed` 均为布尔值 `true`；重复请求不会再次上移。
4. 控制端仅执行一次 `$J=G21 G91 Z-13.5 F100`，等待物理 Idle、检查 XYZ 位移，再用 `G92 X0 Y0 Z0` 建立本次工作原点。未完成此流程前拒绝微动、抬落笔、检查及书写。
5. 完成后按常规流程排版、预览、核对纸张起点并开始书写。任务仍使用逻辑 Z0/Z13.5；控制端将 Z 指令转换为本次校准对应的机器坐标。手动抬落笔、正常结束和终止回位采用相同基准。

此流程不寻找机械原点、不依赖位置传感器，也不跨连接或重启保存校准。断开、异常或检测到非预期固件重启后，必须重新完成流程。程序无法检测手推、丢步和弹簧调整；发生这些情况应主动放弃旧基准，断电重做。校准后禁止用手移动机构。运行中不要换笔或调整弹簧。

`state.position` 仍为控制板 MPos；校准后的 `logical_z` 才是顶部为零的 Z。`calibrated` 表示本次流程是否完成，`startup_mode` 为 `paper-contact`。未经现场确认时，软件不会自动执行上移校准。
